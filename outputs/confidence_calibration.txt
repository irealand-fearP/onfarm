# AI 신뢰도 보정(calibration) 실측 (2026-08-14)

재현:
  python3 tools/dump_conditions.py --n 8 --out DIR --downscale {bilinear|nearest}
  npm run build
  node tools/eval_calibration.mjs --dir DIR --label "라벨"

표본: 상품 사진 16종 × 변형 8장 × 촬영조건 8종 = 1,024 판정 (경로별)
경로: heuristic / CNN(TTA끔) / CNN(TTA켬) — provider_comparison.txt 와 같은 표본·같은 서버 코드

────────────────────────────────────────────────────────────────────────
0. 이 측정의 한계 (결과보다 먼저 읽을 것)
────────────────────────────────────────────────────────────────────────
· 상품 사진은 품목당 1장뿐이다. 변형 8장은 독립 표본이 아니므로 표본 수 1,024 는
  통계적 유효 표본 16 에 가깝다. 구간별 적중률의 신뢰구간은 표시된 것보다 훨씬 넓다.
· heuristic 의 프로토타입 색표는 **바로 이 상품 사진들로 맞춘 값**이다(heuristic.ts 주석).
  heuristic 에게 이 평가는 자기가 공부한 시험지다. 45% 는 상한이지 기대치가 아니다.
· 실제 폰으로 찍은 사진은 0장이다(metadata caveat / field_evaluated: false).
  촬영조건 8종은 전부 합성 변형이다.
· CNN 이 배운 품목은 5종(감귤·감자·배·사과·양파), 우리 카탈로그는 16종이다.
  나머지 11종은 구조적으로 top-1 이 0% 일 수밖에 없다.
· 아래 수치는 전부 **화면에 표시되는 confidence 값** 기준이다(품질계수·상한 적용 후).

────────────────────────────────────────────────────────────────────────
1. 핵심 판정 요약
────────────────────────────────────────────────────────────────────────
(1) heuristic 의 신뢰도 숫자는 정보가 없다.
    상위 50% 신뢰도 구간의 적중률 43.9% vs 하위 50% 45.3% — 차이 -1.4p(오히려 역전).
    구간별 적중률도 34% → 51.6% → 26.1% 로 단조롭지 않다.
    즉 heuristic 이 "0.45" 라고 말할 때와 "0.27" 이라고 말할 때 맞을 확률은 사실상 같다.

(2) 코드에 적힌 신뢰도 상한 두 개는 **둘 다 실제로 작동하지 않는다**.
    · heuristic MAX_CONFIDENCE = 0.86 : 1,024 판정에서 관측된 최댓값은 0.461.
      상한이 한 번도 걸리지 않았다 — 장식이다.
    · CNN capConfidence 천장 = meta.val_object_level.item = 1.0 :
      Math.min(raw, 1.0) 이라 아무것도 자르지 않는다. 관측 최댓값 0.962.
      "화면 최대 86%" 라는 설명 자체가 두 경로 모두에서 사실과 다르다.

(3) CNN(TTA켬)의 신뢰도는 **품목이 학습 어휘 안일 때만** 정보를 갖는다.
    학습 5품목 안: 0.5 이상 구간 적중률 94~100%(단조 증가) — 잘 보정돼 있다.
    미학습 11품목: 모든 구간에서 적중률 0%인데 신뢰도는 0.86까지 올라간다.
    두 집단을 섞으면 최상위 구간이 무너진다(A안 0.8~1.0 구간 15.5%).
    → 문제는 "확률이 부풀려졌다" 가 아니라 **모르는 품목을 모른다고 말하지 못한다** 이다.

(4) 과대평가 폭(ECE, 기대보정오차): heuristic 0.159 / CNN(TTA끔) 0.427~0.514 / CNN(TTA켬) 0.229~0.321.
    CNN(TTA끔)이 가장 위험하다 — 0.7~0.8 이라 말하고 실제 5.1% 를 맞힌 칸이 있다(B안).

────────────────────────────────────────────────────────────────────────
2. 품목별에서 눈에 띄는 것
────────────────────────────────────────────────────────────────────────
· 카탈로그 16종 중 8종(쌀·마늘·포도·감·고등어·새우·오징어·전복)은 세 경로 모두 0%.
  heuristic 도 0% 다 — 이 8종은 프로토타입 색표에도 없다(PROTOTYPES 8종뿐).
  그런데도 평균 신뢰도는 0.28~0.44 로 붙는다. 사용자에게는 판정처럼 보인다.
· CNN 미학습 품목 중 마늘·새우는 CNN 평균 신뢰도가 0.75~0.88 로 가장 높다.
  전부 오답이다. **가장 자신 있게 틀리는 품목**이 화면에서 가장 확신에 차 보인다.
· 감귤은 세 경로 모두 87~100% 로 유일하게 안정적이다.
· 감자는 축소 방식에 따라 CNN(TTA켬)이 14% ↔ 87.5% 로 흔들린다(전처리 민감).

────────────────────────────────────────────────────────────────────────
3. 보정 함수 후보 (측정이 지지하는 것만)
────────────────────────────────────────────────────────────────────────
[제안 1 · 가장 강하게 지지됨] 어휘 밖 품목 게이트
  CNN 은 학습 5품목 밖에서는 적중률이 정확히 0% 다(n=704 / n=666, 모든 신뢰도 구간에서).
  따라서 top-1 이 5품목 밖인 경우가 아니라, **CNN 이 낸 후보 자체가 5품목뿐**이라는 사실을
  신뢰도에 반영해야 한다. 카탈로그 16종 중 11종에는 CNN 판정을 쓰지 않는 것이 옳다.
  근거: 미학습 11품목 CNN top-1 = 0.0% (구간 불문).

[제안 2 · 지지됨] CNN 신뢰도의 구간 매핑(binning / isotonic)
  학습 5품목 안에서 CNN(TTA켬)의 신뢰도는 단조 증가한다:
    A안 0.3~0.4:19% / 0.4~0.5:46% / 0.5~0.6:94% / 0.6~ :100%
    B안 0.3~0.4:35% / 0.4~0.5:99% / 0.5~ :100%
  단조성이 성립하므로 isotonic regression(또는 위 구간표 그대로의 lookup)이 적용 가능하다.
  다만 표본이 독립이 아니므로(품목당 사진 1장) 지금 수치를 그대로 매핑표로 박는 것은 위험하다.
  → 실제 폰 사진이 모이기 전에는 "구간 3~4칸의 거친 매핑" 까지만 권한다.

[제안 3 · 지지됨] 단순 상한 하향 — 단, 지금의 상한 코드는 무력하므로 먼저 살려야 한다
  · CNN: 천장을 val_object_level.item(=1.0, 검증셋 값이라 실전 상한이 아님) 대신
    **실측 상한**으로 바꿔야 상한이 의미를 갖는다. 이 표본이 지지하는 값은
    학습 5품목 CNN(TTA켬) top-1 = 0.74(A) ~ 0.95(B) 중 보수적인 0.74.
    (전체 16종 기준으로 잡으면 0.23~0.30 이지만, 이는 제안 1 로 해결할 문제를
     상한으로 뭉개는 것이라 권하지 않는다)
  · heuristic: 상한 0.86 은 관측 최댓값 0.461 보다 훨씬 높아 무의미하다.
    상한을 0.5 로 낮춰도 이 표본에서 바뀌는 판정은 없다 — 즉 상한 조정은 heuristic 에서
    아무 효과가 없다. heuristic 은 상한이 아니라 (4) 가 필요하다.

[제안 4 · heuristic 에 대한 유일한 결론] 숫자 자체를 쓰지 말 것
  heuristic 신뢰도는 상위/하위 50% 적중률 차이가 -1.4p 로 변별력이 없다.
  변별력이 없는 값에는 어떤 보정 함수도 적용할 수 없다(보정은 순서를 보존하므로,
  순서에 정보가 없으면 보정 후에도 정보가 없다).
  지지되는 유일한 처리: heuristic 경로에서는 사진마다 다른 숫자를 보여주지 말고
  **경로 전체의 실측 적중률(45%, 그것도 자기 시험지 기준)** 하나만 쓰는 것.
  ※ 표시 방식은 UX 설계 소관이므로 이 문서는 수치 근거까지만 제시한다.

[적용하지 않은 것]
  · 온도 스케일링(temperature scaling): 단일 파라미터로 전체를 보정하는 방법인데,
    CNN 의 오보정은 어휘 밖 품목에서 발생하는 이질적 오류라 단일 온도로 고칠 수 없다.
    (미학습 11품목은 온도를 아무리 올려도 적중률이 0% 다)
  · 코드 수정: capConfidence 의 천장값을 이번에 고치지 않았다. 그 값은 metadata 에서 오고,
    metadata 의 1.0 은 '검증셋에서 실제로 측정된 값'이라 임의로 낮춰 적으면 측정 기록이 훼손된다.
    올바른 수정은 metadata 에 실전 상한 필드를 따로 두고 capConfidence 가 둘 중 작은 값을 쓰는 것이며,
    이는 화면 숫자를 바꾸므로 UX 표시 설계와 함께 처리해야 한다.
