# ON-FARM 판매자·소비자 사이트 분리 개편 — 설계

- 작성일: 2026-08-13
- 목적: **공모전 시연용 데모**
- 대상 저장소: `irealand-fearP/onfarm` (원본 `latemo/onfarm`의 포크, 기본 브랜치 `master`)

## 1. 배경

기존 온팜은 기능이 아니라 **진입 구조**에 문제가 있다. 실제로 서버를 띄워 확인한 결과:

- 등록 흐름은 이미 **탭 5회·텍스트 입력 0회**로 완결된다 (가격·제목·소개·수확일 전부 서버 생성).
- TTS 낭독(0.92배속), "1번"→"일번" 교정, "다섯 상자" 음성 수량 파싱이 모두 동작한다.
- "AI는 가격을 만들지 않고 등급을 확정하지 않는다"는 원칙이 스키마·UI·라우트에 일관되게 구현돼 있다.

즉 **좋은 기능이 잘못된 문 뒤에 숨어 있다.** 기능을 추가하지 않고 입구와 밀도만 다시 설계한다.

### 확인된 문제 4가지

1. 판매자가 접속하면 **소비자 매장**이 첫 화면이다.
2. `/farmer`로 직행해도 **계정 9개 목록**(농민4·소비자2·거점2·운영자1)이 먼저 뜬다. 고령 사용자에게는 여기가 벽이다.
3. 판매자 홈에 정보가 과다하다. 핵심 버튼 아래로 주문·상품·정산·AI설명이 이어지고, 하단 5탭 내비에서 "등록"이 5분의 1로 묻힌다.
4. 소비자 상품이 전부 일러스트이며 카드마다 "실제 사진 아님"이 붙는다. 직거래의 핵심인 신뢰가 첫 화면에서 깎인다.

## 2. 목표와 비목표

**목표**
- 판매자와 소비자가 서로 다른 문으로 들어간다.
- 판매자는 접속 즉시 등록을 시작한다.
- 소비자는 가격보다 생산자와 검수 상태를 먼저 본다.
- 고령 사용자와 젊은 판매자가 같은 디자인을 쓰되 밀도만 다르다.

**비목표 (이번 범위 밖)**
- 실결제(PG) 연동, 본인확인 인증, 영구 DB/스토리지 전환
- 거점 화면의 기능 변경
- AI 파이프라인·음성 기능 수정

## 3. 구조

서버 1개·DB 1개를 유지한다. 주문·재고·정산이 세 화면에서 그대로 이어져야 하므로 저장소를 쪼개지 않는다.

| 사이트 | 주소(도메인 보유 시) | 주소(도메인 없이) | 대상 |
|---|---|---|---|
| 판매자 | `seller.<도메인>` | `/seller` | 농민 |
| 소비자 | `<도메인>` | `/` 또는 `/shop` | 구매자 |
| 거점 | `/hub` | `/hub` | 거점 담당자·운영자 |

**분기 규칙**: `Host` 헤더가 `seller.`로 시작하면 판매자 사이트, 그 외에는 소비자 사이트. 경로가 `/seller`로 시작하면 Host와 무관하게 판매자 사이트. 도메인이 없어도 시연이 가능해야 하므로 경로 분기를 항상 함께 지원한다.

기존 `/farmer`, `/store` 경로는 각각 `/seller`, `/shop`으로 **301 리다이렉트**해 팀원이 공유한 기존 링크를 깨뜨리지 않는다.

### CSS 파일 분리 (선행 필수)

현재 `public/css/store.css`(2374줄)가 **소비자 + 로그인 + 데모 + 거점**을 모두 담당한다. 소비자 화면을 개편하면 거점 화면이 함께 깨진다. 따라서 화면 작업 전에 먼저 분리한다.

| 파일 | 담당 |
|---|---|
| `base.css` | 디자인 토큰, reset, 뱃지·토스트·스피너 등 공용 요소 |
| `seller.css` | 판매자 전용 |
| `shop.css` | 소비자 전용 |
| `hub.css` | 거점 전용 (store.css에서 떼어냄, 시각적 변화 없이) |

## 4. 디자인 시스템

### 색

버튼과 강조는 밝은 그린 하나로 통일하고, 배너·분류 타일에만 파스텔을 얇게 깐다. 글자와 배경은 전부 무채색이다.

| 토큰 | 라이트 | 용도 |
|---|---|---|
| `--bg` | `#FFFFFF` | 기본 배경 |
| `--bg-2` | `#F2F4F6` | 카드·구분 면 |
| `--t1` | `#191F28` | 본문 글자 |
| `--t2` | `#4E5968` | 보조 글자 |
| `--t3` | `#8B95A1` | 흐린 글자 |
| `--brand` | `#00C46A` | 주 버튼·강조 |
| `--brand-tint` | `#E4F9EE` | 선택 상태 배경 |
| `--alert` | `#FF4D5E` | 알림 배지 전용 |
| `--peach` | `#FFE3D2` | 배너 |
| `--lilac` | `#EAE4FF` | 분류 타일 |
| `--butter` | `#FFF1C9` | 분류 타일 |

다크 모드 토큰도 동일 구조로 정의한다. 색은 반드시 토큰을 거쳐 사용하고, 미디어쿼리 안에서만 정의되는 색을 만들지 않는다.

### 타이포

- 폰트: **Pretendard를 프로젝트에 직접 포함**한다(CDN 금지 — 오프라인·심사장 네트워크 실패 대비). woff2 서브셋을 `public/fonts/`에 두고 `@font-face`로 로드하며, 실패 시 `Apple SD Gothic Neo`/`Malgun Gothic`으로 폴백한다.
- 제목 자간 `-0.04em`, 굵기 800. 숫자는 `font-variant-numeric: tabular-nums`.
- 한글 줄바꿈은 `word-break: keep-all`을 유지한다.

### 밀도 2단계 (핵심 결정)

고령 사용자에게 맞춘 큰 UI가 젊은 판매자에게는 촌스럽게 읽힌다. 디자인을 두 벌 만들지 않고 **기준 단위 하나만 바꿔** 해결한다.

```css
body.seller            { --u: 1;    }  /* 크게 — 기본값 */
body.seller[data-density="compact"] { --u: 0.82; }  /* 보통 */
```

글자·버튼 높이·여백·아이콘을 전부 `--u`에 비례시킨다.

| | 크게 (기본) | 보통 |
|---|---|---|
| 본문 | 19px | 16px |
| 주 버튼 최소 높이 | 68px | 52px |
| 수량 스테퍼 | 82px | 64px |

- 전환: 판매자 화면 우측 상단의 작은 `가⁺ / 가⁻` 버튼 1탭.
- 저장: `localStorage`. 다음 방문에 유지된다.
- 기본값은 **크게**. 고령 사용자가 아무것도 하지 않아도 손해 보지 않는다.
- 색·형태·구조는 두 밀도에서 완전히 동일하다.

**촌스러움을 만드는 요인은 크기가 아니라** ① 넓은 면적의 원색 ② 밀도 리듬 없는 휑함 ③ 훈계조 문구 ④ 이모지·일러스트 남발이다. 문구는 담백한 명사형으로 통일하고, 큰 요소 옆에는 반드시 작은 보조 정보를 배치해 리듬을 만든다.

## 5. 판매자 사이트

### 화면 구성

기존 5개 화면 + 하단 5탭 내비를 **3개 화면**으로 줄인다.

| 경로 | 화면 | 내용 |
|---|---|---|
| `/seller` | 시작 | 농가명 + 밀도 토글 / 대형 사진 버튼 / "오늘 할 일" 요약 1줄 |
| `/seller/sell` | 등록 | 사진 → 품목 → 수량(최종확인 포함) → 완료 |
| `/seller/todo` | 오늘 할 일 | 보낼 주문 · 판매 중 상품 · 받을 돈을 한 페이지에 통합 |

- **홈 대시보드를 삭제한다.** 접속 즉시 등록 1단계다.
- **하단 5탭 내비를 제거한다.** 이동 경로는 "오늘 할 일" 하나뿐이다.
- 기존 `farmer/orders.html`·`listings.html`·`settlement.html`의 기능은 `/seller/todo` 한 페이지의 세 섹션으로 합친다. 기능 삭제는 없다.

### 자동 로그인 (데모 한정)

판매자 사이트 진입 시 세션이 없으면 기본 농민 계정으로 **자동 세션을 발급**한다. 로그인 화면을 보여주지 않는다.

- 계정 전환은 우측 상단 "농가 바꾸기" → 농민 4명만 큰 카드로 표시.
- **`DEMO_AUTO_LOGIN=true`(기본값)일 때만 동작**한다. 이 환경변수가 꺼지면 기존 로그인 흐름으로 돌아간다.
- 화면 하단에 "시연용 계정" 표기를 유지한다. 인증 우회를 숨기지 않는다.
- 소비자·거점 사이트에는 적용하지 않는다.

### 등록 흐름

탭 5회 → **4회**로 줄인다.

1. 사진 선택 (`capture="environment"`)
2. 분석 중
3. **품목 고르기** — 후보가 1개여도 반드시 고르게 한다. *(현행 유지. 오등록 방지 장치이므로 축소 금지)*
4. **수량 + 최종 확인** — 기존 `stepSku`와 `stepConfirm`을 한 화면으로 합친다. 상단에 품목·단위·단가, 중앙에 스테퍼, 하단에 합계와 "이대로 팔기".
5. 완료 — "하나 더 올리기" / "그만하기" 2개만.

진행 표시를 실제 단계 수와 맞춘다(현재 6개 섹션인데 "1/4"로 표기되는 불일치 수정). 사진·품목·수량 3단계 기준 `1/3 ~ 3/3`.

**서버 계약은 바꾸지 않는다.** `POST /api/ai/analyze`, `POST /api/farmer/listings`의 요청·응답 형식과 `analysisId` 소진 로직을 그대로 쓴다. 기존 테스트가 계속 통과해야 한다.

## 6. 소비자 사이트

| 경로 | 화면 |
|---|---|
| `/` (또는 `/shop`) | 산지 목록 |
| `/shop/product?id=` | 상세 |
| `/shop/cart` | 장바구니·주문 |
| `/shop/orders` | 주문 내역·배송 추적 |

### 홈 구성

1. 검색바
2. **피치 배너** — "해 뜨자마자 딴 것만 모아 봤어요"
3. **퀵 타일 3개** — 검수 완료 / 오늘 수확 / 마감 임박
4. 지역·품목 칩
5. 상품 그리드 2열 — 품목별 파스텔 타일 배경 위에 상품 이미지
6. 하단 탭바 5개 — 홈·검색·찜·주문·내정보

### 신뢰 요소

- 카드에 **농가 이름과 생산자 표시를 가격 위에** 둔다.
- "검수 완료" 배지를 이미지 좌상단에 고정한다.
- 상세 화면은 이미지 → **생산자 카드** → 검수 타임라인 → 구매바 순서.
- AI 등급은 계속 "참고 판정", 확정 등급은 거점 검수 결과로만 표기한다. **이 구분을 절대 흐리지 않는다.**

### 상품 이미지

일러스트를 AI 생성 실사 이미지로 교체한다. 시드 품목 9종 전부.

- 저장 위치: `public/img/products/<code>.webp`
- 이미지에 **"시연용 이미지"** 배지를 표시한다. 실제 농민이 올린 사진과 시드 이미지를 화면에서 구분한다.
- 농민이 실제 촬영해 등록한 상품은 업로드된 사진을 그대로 쓰며 이 배지를 붙이지 않는다.

## 7. 유지할 것

아래는 이번 개편에서 **건드리지 않는다.**

| 영역 | 이유 |
|---|---|
| AI 파이프라인 5단계 | 견고하고 테스트가 덮고 있음 |
| TTS·STT·한국어 수량 파서 | 완성도가 높음 |
| SKU 가격 단일 출처 원칙 | 심사 차별점 |
| AI 참고 등급 ↔ 거점 확정 등급 분리 | 심사 차별점 |
| 역할 접근 제어·거점 스코프 격리 | 보안 |
| DB 스키마 | 변경 불필요 |
| 거점 화면 기능 | 범위 밖 (CSS만 분리) |

## 8. 구현 순서

각 단계가 끝날 때마다 `npm test`가 통과해야 하고, 실제 브라우저에서 화면을 확인한다.

**Phase 1 — 기반 정리**
1. Pretendard 폰트 프로젝트에 포함
2. `base.css` 토큰을 새 팔레트로 교체
3. `store.css`에서 거점을 `hub.css`로 분리 (거점 화면 시각적 변화 0 확인)

**Phase 2 — 라우팅**
4. Host/경로 기반 사이트 분기
5. `/farmer`·`/store` → `/seller`·`/shop` 리다이렉트
6. `DEMO_AUTO_LOGIN` 자동 세션

**Phase 3 — 판매자**
7. `seller.css` 작성 (밀도 `--u` 시스템 포함)
8. `/seller` 시작 화면
9. `/seller/sell` 등록 흐름 (수량+확인 통합, 진행 표시 수정)
10. `/seller/todo` 통합 페이지
11. 밀도 토글 + localStorage

**Phase 4 — 소비자**
12. `shop.css` 작성
13. 홈 (배너·퀵타일·그리드·탭바)
14. 상세 (생산자 카드·타임라인)
15. 장바구니·주문 내역
16. 상품 이미지 9종 교체

**Phase 5 — 마무리**
17. 전 화면 다크 모드 점검
18. 모바일 실기기 폭(360~430px) 확인
19. `/demo` 시연 시작점 갱신
20. Vercel 배포

## 9. 위험과 대응

| 위험 | 대응 |
|---|---|
| Vercel의 SQLite·업로드가 콜드 스타트에 초기화됨 | 시연 직전 `npm run seed` 상태로 배포하고, 심사 당일 리셋 절차를 대본에 포함. 영구 저장소 전환은 범위 밖 |
| 화면 개편 중 기존 테스트 파손 | 서버 계약을 바꾸지 않는다. Phase마다 `npm test` 실행 |
| 거점 화면 동반 파손 | CSS 분리를 Phase 1에서 선행하고 분리 직후 거점 화면을 육안 확인 |
| 자동 로그인이 보안 구멍으로 오해됨 | 환경변수로 끌 수 있게 하고 화면에 "시연용" 표기 유지 |
| 폰트 CDN 실패로 심사장에서 폰트 깨짐 | 폰트 파일을 저장소에 포함 |

## 10. 완료 기준

- 판매자 주소로 접속해 **로그인 화면 없이** 사진 버튼이 보인다.
- 등록이 **탭 4회**로 끝난다.
- 밀도 토글로 크게/보통이 전환되고 새로고침 후에도 유지된다.
- 소비자 홈에 배너·퀵타일·생산자 표시가 보이고 상품 이미지가 실사다.
- 거점 화면이 개편 전과 동일하게 동작한다.
- `npm test` 전부 통과.
- 라이트·다크 두 테마에서 모든 화면이 읽힌다.
