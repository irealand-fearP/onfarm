- 화면: 1920×1080 / 30fps
- 오디오: **서버 TTS(Supertonic, 화자 F1) 나레이션 + 자막 병행** — 2026-09-10 확정. 배경음은 없거나 아주 낮게

## 왜 다시 만드는가 (기존 영상 결함)

1. 실측 24초인데 README에는 "약 84초" — 제출물끼리 안 맞는다
2. 무음이라 근거를 말로 못 한다 (자막만으로는 정보량이 안 나온다)
3. 20초 지점에서 자막 두 장이 겹쳐 렌더링된다
4. 거점 화면이 **0건 / "처리할 상품이 없습니다"** — 기획서의 "목업 아님" 주장을 스스로 깎는다
5. 천안 데이터 근거(9,488 → 7,232 / 65.1세)가 영상에 한 번도 안 나온다

## 컷 구성

### [0:00–0:12] 컷1 · 문제 — 왜 천안인가 (심사: 주제적합·데이터이해)

**화면**
- 검은 화면에서 숫자만 크게 올라온다. 애니메이션 카운트업.
  `9,488` → 아래에 `천안시 농가` (KOSIS 2024)
- 숫자가 갈라진다: `2,256` 로컬푸드 참여 / **`7,232` 체계 밖** (빨강 아님, 회색 → 강조색)
- 하단에 작게: `평균 65.1세 · 60대 이상 70% · 경지 1ha 미만 77%`

**나레이션**
> "천안 농가 9,488가구 중 로컬푸드 체계 안에 있는 곳은 2,256가구입니다.
> 나머지 7,232가구는 평균 예순다섯 살이 짓는 작은 농가입니다."

**자막(하단 고정)**
`출처: KOSIS DT_1EA1011(2024) · DT_1AG20107(2020) · 산출 스크립트 동봉`

> ⚠️ 반드시 출처를 화면에 박는다. 이 한 줄이 '데이터 이해' 점수다.

### [0:12–0:24] 컷2 · 원인 — 판로가 아니라 등록 (심사: 창의)

**화면**
- 일반 직거래 앱의 등록 폼을 재현한 화면. 입력칸 6개가 순서대로 뜬다:
  `상품명 / 카테고리 / 중량·규격 / 가격 책정 / 상세 설명 / 사진 편집`
- 칸들이 하나씩 붉은 테두리로 막히며 `✕` 표시
- 화면 전체가 어두워지고 가운데 한 줄: **"판로가 없는 게 아니라, 등록을 못 한다"**

**나레이션**
> "판로가 없어서가 아닙니다. 기존 앱은 농가가 이 여섯 칸을 채울 수 있다고 전제합니다.
> 고령 소농에게는 이 여섯 칸이 곧 장벽입니다."

### [0:24–0:54] 컷3 · 해법 실연 — 사진 한 장에서 판매까지 (심사: 활용 / **가장 중요**)

**화면 — 실제 앱 조작 녹화. 여기서만 30초를 쓴다.**
- 우측 상단에 **경과시간 타이머**를 계속 띄운다 (`00:00`부터 실시간). 끝나면 멈춰서 강조.
- 좌측 하단에 **탭 카운터** (`탭 1회 → 2회 → 3회 → 4회`)

| 초 | 조작 | 화면 포인트 |
|---|---|---|
| 0:24 | `/seller` 주소 입력 → 접속 | **로그인 화면이 없다.** 바로 김복순님 홈, 초록 [사진 찍기] 버튼 하나 |
| 0:30 | [사진 찍기] → 배 사진 선택 | 실제 폰으로 찍은 배 사진 |

| 0:42 | 단위·수량 화면 | `5kg 한 상자 29,000원` / 화면 문구 클로즈업: **"운영자가 미리 정한 표준 가격입니다. AI가 가격을 정하지 않습니다."** |

**나레이션**
> "농가가 하는 일은 세 가지입니다. 사진을 찍고, 번호를 고르고, 수량을 확인합니다.

### [0:54–1:10] 컷4 · 신뢰 설계 — AI가 하지 않는 일 (심사: 기획·데이터이해)

**화면**
- 3분할 카드가 차례로 뒤집힌다.

| 카드 | 앞면 | 뒷면(강조) |
|---|---|---|
| 가격 | AI가 정하지 않는다 | 운영자 표준 정찰가 — 화면 문구 실물 캡처 |
| 등급 | 확정이 아닌 참고값 | 확정은 거점의 실물 검수 |
| 신뢰도 | 85%를 넘지 못한다 | `src/ai/policy.ts` 코드 한 줄 클로즈업 |

- 이어서 **양파 그래프**(grade.png)를 띄운다. AI 38.8% vs 무게만 쓰는 기준선 73.8%.
- 그 위로 문구: **"그래서 양파 등급은 화면에 표시하지 않습니다."**
- 실제 앱에서 양파 등록 → 등급 배지가 안 뜨는 화면을 1.5초 보여준다.

**나레이션**
> "AI가 잘하는 것만 말하지 않겠습니다. 양파는 AI가 무게만 쓰는 단순 규칙보다 못했습니다.
> 그래서 양파 등급은 화면에 아예 표시되지 않습니다. 발표에서 숨기는 게 아니라, 코드가 막습니다."

> ⚠️ 이 컷이 이 영상의 차별점이다. 대부분의 출품작은 잘된 숫자만 보여준다. 못한 숫자를 먼저 말하는 30초가 심사위원에게 남는다.

### [1:10–1:22] 컷5 · 한 바퀴 — 데이터가 실제로 흐른다 (기존 영상의 치명적 결함 교정)

**화면 — 세 화면을 빠르게 오간다. 반드시 데이터가 채워진 상태로.**
- `/shop` 소비자 화면: **방금 올린 배가 목록 맨 위에** 떠 있다 → 담기 → 주문
- `/hub` 거점 화면: **검수 필요 `1`** 카운터가 켜져 있다 → [입고 확인] → [검수 통과] → 배송 준비
- `/seller` 판매자 화면: **받을 돈에 29,000원이 올라온다**

**나레이션**
> "방금 올린 배가 소비자 화면에 뜨고, 거점이 실물을 검수해 등급을 확정하고,
> 어르신 정산에 금액이 올라옵니다. 세 화면이지만 데이터는 하나입니다."

> ⚠️ **촬영 전 데모 데이터를 반드시 시드한다.** 0건 화면이 한 프레임도 나오면 안 된다.
> 기존 영상은 여기서 "처리할 상품이 없습니다"를 그대로 내보냈다.

## 제작 방법 (확정 후 진행)

1. **실제 앱 조작 녹화** — 로컬에서 `npm run seed && npm start` → Playwright로 조작 스크립트를 짜서 일정한 속도로 재현, 화면 녹화. 손떨림·오조작 없이 매번 같은 영상이 나온다.
2. **나레이션** — 저장소에 이미 붙어 있는 서버 TTS(Supertonic, 화자 F1) 재사용. 톤·속도가 앱 음성안내와 같아 일관성이 생긴다.
3. **합성·자막** — ffmpeg로 컷 연결 + 자막 번인. (현재 WSL에 ffmpeg 미설치 → 설치 필요)
4. **검수** — 완성본에서 ① 0건 화면 없음 ② 자막 겹침 없음 ③ 출처 표기 존재 ④ README 표기 길이와 실제 길이 일치 를 프레임 단위로 확인한다.
