# 판매 안내 모드(가이드 모드) 설계 스펙

작성: UX / 대상: dev
목적: 참고 사이트(onfarm-zeta `/farmer`)의 "안내 켜짐" 온보딩을, 우리 판매자 5화면 구조·색·밀도토글을 깨지 않는 선에서 **위에 얹는다**.

## 0. 설계 원칙 (먼저 합의할 것)

1. **기존 화면을 바꾸지 않는다.** 안내 모드는 기존 DOM에 클래스와 작은 안내 블록만 얹는다. 안내를 끄면 지금 화면과 픽셀 단위로 같아야 한다.
2. **새 색을 만들지 않는다.** 참고 사이트의 "금색 테두리"는 우리 팔레트에 없다. 우리는 이미 있는 `--brand`(#00c46a)를 강조색으로 쓰고, 보조 강조가 필요하면 `--butter`/`--butter-ink`(이미 base.css에 있음)만 쓴다. 이유: 어르신 화면에서 색이 3개 넘어가면 "어디를 봐야 하는지"가 오히려 흐려진다.
3. **가리키는 곳은 한 화면에 하나.** 화살표·펄스·툴팁을 동시에 쓰지 않는다. 강조 대상이 둘이면 강조가 아니다.
4. **모든 치수는 `--u` 기준.** 안내 모드 전용 px 하드코딩 금지. 밀도토글과 자동으로 같이 커지고 작아진다.
5. **AI 원칙 유지.** 안내 문구는 "저희가 도와드립니다" 톤. "AI가 알아서 팝니다" 식 표현 금지.

## 1. 안내 토글 — 위치·기본값·저장

### 1-1. 위치
헤더 `.s-head-actions` 안, **밀도토글 왼쪽**에 둔다.

```
[ 홍길동님 ]                    [시연▾] [안내 켜짐] [가⁻] [농가 바꾸기]
```

- 밀도토글(`#densityBtn`)보다 왼쪽 = 스캔 순서상 먼저 읽힌다. 안내가 밀도보다 상위 개념이라서다.
- 시연 메뉴(`#demoNavSlot`)는 그대로 맨 왼쪽. 발표자용 보조 수단이므로 순서 유지.
- **판매자 홈(index.html)에만 토글을 노출한다.** sell/orders/products/money 헤더에는 토글을 넣지 않는다. 이유: 등록 중에 안내를 껐다 켰다 하는 건 실제 필요가 없고, 헤더 칩이 4개를 넘으면 어르신 화면에서 줄바꿈이 난다. 다른 화면은 저장된 값을 **읽어서 반영만** 한다.

### 1-2. 표기
밀도토글의 표기 규칙("지금 무엇을 할 수 있는지"가 아니라 **지금 상태**를 읽히게)과 통일한다. 밀도토글은 "다음 행동"을 쓰지만, 안내는 상태 자체가 정보이므로 **현재 상태 표기**로 간다. 이 불일치는 의도된 것이며, 대신 안내 토글은 스위치 모양(●─)으로 그려 버튼과 시각적으로 구분한다.

| 상태 | 버튼 텍스트 | 시각 |
|---|---|---|
| ON | `안내 켜짐` | 초록 배경(`--brand-tint`) + 초록 글자(`--brand-strong`) + 채워진 점 |
| OFF | `안내 꺼짐` | 기본 칩(회색 테두리) + 빈 점 |

### 1-3. 기본값
**첫 방문은 ON.** (밀도 기본값 '크게'와 같은 철학 — 아무것도 하지 않은 사용자가 손해 보지 않는다.)
단, **자동 졸업 규칙**을 둔다: 판매 등록을 **3회 완료**하면 다음 홈 진입 시 안내를 자동으로 OFF로 내리고, 홈 상단에 1회성 안내 줄을 띄운다.

> "이제 익숙해지셨네요. 안내를 껐습니다. 다시 보시려면 오른쪽 위 '안내'를 눌러 주세요."

이유: 어르신도 3번이면 손이 기억한다. 계속 "지금 할 일" 배지가 붙어 있으면 화면이 늘 초보자 모드로 보여 오히려 불쾌하다. 사용자가 직접 토글을 만진 뒤에는 자동 졸업을 두 번 다시 적용하지 않는다(아래 `manual` 플래그).

### 1-4. 저장 (localStorage)
`seller-density.js`와 같은 네임스페이스 규칙을 따른다.

| 키 | 값 | 설명 |
|---|---|---|
| `onfarm.seller.guide` | `'on'` \| `'off'` | 안내 모드 상태. 없으면 `'on'` |
| `onfarm.seller.guide.manual` | `'1'` | 사용자가 토글을 직접 누른 적 있음. 있으면 자동 졸업 안 함 |
| `onfarm.seller.sellCount` | 숫자 문자열 | 등록 완료 횟수. `stepDone` 도달 시 +1 |

읽기/쓰기는 전부 try/catch (density 모듈과 동일 — 사파리 프라이빗 모드 대비).

### 1-5. 새 모듈 `web/js/seller-guide.js`
`seller-density.js`와 판박이 구조로 만든다.

```js
export function guideOn()                  // boolean, 저장값 해석(기본 on)
export function applyGuide(on)             // body[data-guide="on"] 토글 + 저장 + 반환
export function mountGuideToggle(selector) // 홈 전용: 버튼 렌더 + 클릭 핸들러 + aria
export function bumpSellCount()            // 등록 완료 시 호출, 3회 도달 시 자동 졸업 처리
export function consumeGraduationNotice()  // 졸업 안내 줄을 1회만 보여주기 위한 소비형 조회
```

- 모듈 로드 즉시 `applyGuide(guideOn())`을 한 번 실행해 깜빡임 방지 (density와 동일).
- **모든 판매자 화면에서 이 모듈을 import**한다(토글 버튼은 홈만, 상태 반영은 전체).
- 스타일 훅은 `document.body`의 `data-guide="on"` 속성 하나. OFF면 속성을 제거한다.

## 2. 안내 ON일 때 홈 화면(`web/seller/index.html`)

### 2-1. 우리 3단계가 맞는가 — 확인
맞다. `seller-sell.js`의 `STEP_PROGRESS`가 이미 **1/3 사진 → 2/3 품목 → 3/3 수량**으로 정의돼 있고, `stepLoading`은 1/3에, `stepManual`은 2/3에 접혀 있다. 홈의 단계 인디케이터는 이 상수와 **같은 라벨 문자열**을 써야 한다.

> dev 주의: 라벨을 홈에 다시 타이핑하지 말고, `STEP_PROGRESS`에서 라벨 3개를 뽑는 작은 상수를 `web/js/shared/`로 빼서 sell과 홈이 같은 출처를 보게 할 것. 두 곳에 글자를 따로 쓰면 나중에 반드시 어긋난다.

홈에 표기할 3단계 라벨(짧은 형):

```
① 사진  ——  ② 품목 확인  ——  ③ 수량 확인
```

### 2-2. 화면 구성 (ON일 때만 추가되는 것)

```
┌ 헤더 ────────────────────────────────┐
│ 홍길동님        [시연▾][안내 켜짐][가⁻][농가 바꾸기] │
└──────────────────────────────────────┘

  ▸ 안내 헤드라인 (신규, ON에서만)
    처음부터 따라 하기
    지금 해야 할 곳만 크게 보여 드립니다

┌ 사진 버튼 (기존 .shoot, 강조만 추가) ──┐
│  [지금 할 일]  ← 배지, 카드 좌상단      │
│         (카메라 아이콘)                │
│         사진 찍기                      │
│    찍으면 나머지는 저희가 합니다        │
│ ──────────────────────────────────── │
│  ① 사진 —— ② 품목 확인 —— ③ 수량 확인 │  ← 카드 하단 단계 줄
└──────────────────────────────────────┘
  아래 큰 버튼을 눌러 판매 등록을 시작하세요   ← 카드 바로 아래 한 줄

  🎙 음성 안내 켜짐            (기존 .mic 그대로)

  [보낼 주문] [판매 중 상품] [받을 돈]  (기존, ON에서 살짝 낮춤)
```

### 2-3. 컴포넌트 단위 명세

**(A) `.guide-lead` — 안내 헤드라인**
- 위치: `.s-body` 최상단, `.shoot` 바로 위. ON일 때만 DOM에 표시(`hidden` 토글).
- 마크업:
  ```html
  <div class="guide-lead" id="guideLead" hidden>
    <strong>처음부터 따라 하기</strong>
    <span>지금 해야 할 곳만 크게 보여 드립니다</span>
  </div>
  ```
- 스타일: 배경 없음(투명), 좌측 정렬, `strong`은 `--fs-lg`/800/`--t1`, `span`은 `--fs-sm`/`--t2`. 카드로 만들지 않는다 — 카드가 늘면 진짜 눌러야 할 카드가 묻힌다.

**(B) `.shoot.is-guided` — 사진 버튼 강조**
- 기존 `.shoot`에 클래스만 추가. `body[data-guide="on"] .shoot`로 CSS를 걸어도 되지만, JS에서 명시 클래스를 붙이는 편이 나중에 "다음 할 일이 사진이 아닌 경우"(4-3 참고)로 확장하기 쉽다.
- 강조 방법: **테두리 + 아주 옅은 배경**만.
  ```css
  body[data-guide='on'] .shoot {
    border: calc(3px * var(--u)) solid var(--brand);
    box-shadow: 0 0 0 calc(4px * var(--u)) var(--brand-tint);
  }
  ```
- **금색 대신 브랜드 그린을 쓰는 이유**: 참고 사이트는 금색이 화면의 유일한 강조였지만, 우리 화면은 이미 그린이 주요 행동색이다. 여기에 금색을 더하면 "초록도 눌러야 하고 금색도 눌러야 하나?"가 된다. 강조는 색을 늘리는 게 아니라 대비를 늘리는 것.
- **애니메이션 금지.** 펄스·바운스 없음. 대신 정지 상태의 링 하나. 이유: 어르신 사용자에게 움직이는 테두리는 "누르면 안 되는 것"처럼 읽히거나, 저사양 기기에서 스크롤을 끊는다.

**(C) `.now-badge` — "지금 할 일" 배지**
- 위치: `.shoot` 내부 좌상단 (`position:absolute; top/left: calc(12px * var(--u))`). `.shoot`에 `position:relative` 추가 필요.
- 마크업: `<span class="now-badge">지금 할 일</span>`
- 스타일: 배경 `--brand`, 글자 `--on-brand`, `--fs-xs`/800, radius 999px, 세로 패딩 `calc(4px*var(--u))`.
- 접근성: 배지는 장식이 아니라 정보다. `aria-hidden` 금지. 대신 버튼의 접근 이름이 "지금 할 일 사진 찍기 …"로 자연스럽게 읽히도록 배지를 버튼 안 첫 자식으로 둔다.

**(D) `.guide-steps` — 3단계 인디케이터**
- 위치: `.shoot` **안쪽 하단**(참고 사이트와 동일). 버튼 밖에 두면 "이것도 눌러야 하나" 오인이 생긴다. 버튼 안이므로 클릭은 통째로 사진 찍기 하나.
- 마크업:
  ```html
  <span class="guide-steps" aria-hidden="true">
    <span class="gs is-now"><i>1</i>사진</span>
    <span class="gs"><i>2</i>품목 확인</span>
    <span class="gs"><i>3</i>수량 확인</span>
  </span>
  ```
- `aria-hidden="true"`인 이유: 같은 정보를 (E)의 안내문과 버튼 접근 이름이 이미 음성으로 전달한다. 스크린리더에서 "1 사진 2 품목 3 수량"이 두 번 읽히면 방해다.
- 스타일: 가로 3칸, 사이는 `1px` 연결선(`--line-strong`), 숫자는 원형 뱃지 `calc(20px*var(--u))`. 현재 단계(`.is-now`)만 `--brand` 채움 + 글자 `--on-brand`, 나머지는 `--line-strong` 테두리 + `--t3` 글자.
- 홈에서는 **항상 ①이 현재 단계**다(등록 전이므로).

**(E) `.guide-hint` — 카드 아래 안내문**
- 마크업: `<p class="guide-hint" id="guideHint">아래 큰 버튼을 눌러 판매 등록을 시작하세요</p>`
- 위치: `.shoot` 바로 아래, 기존 `.mic` 줄 **위**.
- 문구는 "위/아래" 같은 방향어를 쓰되 화살표 아이콘은 넣지 않는다(화살표 남발 지양). 카드 바로 밑이므로 "아래 큰 버튼" 대신 **"위의 큰 버튼을 눌러 시작하세요"** 가 물리적으로 맞다. 참고 사이트 문구를 그대로 베끼지 말고 우리 배치에 맞춘다.
  - 확정 문구: **`위의 큰 버튼을 눌러 판매 등록을 시작하세요`**
- 스타일: `--fs-sm`, `--t2`, 가운데 정렬.
- `aria-live` 붙이지 않는다. 화면 진입 시 자동 낭독은 이미 `.mic` 음성 안내가 담당한다.

**(F) 하단 메뉴 3종 — ON일 때 처리**
- **숨기지 않는다.** 주문·정산은 안내 모드와 무관하게 오늘 확인해야 할 정보다.
- 대신 `body[data-guide='on'] .s-menu { opacity: .92; }` 정도의 아주 약한 후퇴만. 그 이상 흐리면 "고장 났나"로 읽힌다.
- 단, **보낼 주문이 1건 이상이면 후퇴시키지 않는다**(`#orderBadge`가 보이는 경우 `.s-menu`에 `.has-urgent` 부여 → opacity 1). 안내보다 실제 주문이 우선.

### 2-4. 졸업 안내 줄
`consumeGraduationNotice()`가 true를 돌려주면 `.s-body` 최상단에 1회성 줄을 렌더.
```html
<p class="guide-graduate">이제 익숙해지셨네요. 안내를 껐습니다. 다시 보시려면 오른쪽 위 <b>안내</b>를 눌러 주세요.</p>
```
스타일: `--butter` 배경, `--warn` 글자, radius `--radius-card`, 패딩 `--pad`. 닫기 버튼 없음(다음 진입 시 자동 소멸).

## 3. 안내 OFF일 때

`body`에서 `data-guide` 속성이 사라지므로:

- `.guide-lead` / `.guide-hint` → `hidden`
- `.now-badge` / `.guide-steps` → `hidden` (DOM에는 남기고 표시만 끔 — 토글 시 재렌더 없이 즉시 반응)
- `.shoot` 테두리·링 → 기본값 복귀
- `.s-menu` opacity → 1
- **현재 index.html과 완전히 동일한 화면이 되어야 한다.** dev는 OFF 상태에서 스크린샷 비교로 회귀 확인할 것.

토글은 페이지 새로고침 없이 즉시 반영(속성 하나 토글이므로 자연스럽게 됨). transition은 `opacity .15s`만 허용, 테두리는 즉시.

## 4. 등록 화면(`web/seller/sell.html`)에서의 연속성

### 4-1. 이미 있는 것 — 중복 만들지 말 것
sell.html에는 **이미 `.prog` 진행 표시가 있다**: `1 / 3 · 사진 찍기 · 곧 끝납니다` + 진행 바. 이건 `role="progressbar"`로 접근성까지 붙어 있다.
따라서 **"2/3 품목 확인" 같은 표시를 새로 만들 필요가 없다.** 요청하신 항목 4의 답은:

> **새 표시를 추가하지 않고, 기존 `.prog`를 안내 ON에서 "홈에서 본 것과 같은 모양"으로 승격시킨다.**

### 4-2. 안내 ON일 때 `.prog` 승격
`body[data-guide='on'] .prog`에서만:
1. 진행 바(`.pb`) 위에 홈과 **똑같은 `.guide-steps` 3칸 인디케이터**를 함께 렌더한다(같은 CSS 컴포넌트 재사용). 홈에서 본 ①②③이 등록 화면에도 이어져 나오는 게 "연속성"의 핵심이다.
2. 현재 단계 숫자를 크게: `.prog .pt b`를 `--fs-lg`/900로.
3. 힌트 문구(`#progressHint`)를 유지하되 ON에서는 **행동 지시형**으로 바꾼다.

| step | OFF 힌트(현행) | ON 힌트 |
|---|---|---|
| stepPhoto | 한 장이면 됩니다 | 농산물이 꽉 차게 한 장 찍어 주세요 |
| stepLoading | 잠시만요 | 잠시만요 |
| stepResult | 거의 다 됐어요 | 맞는 것을 눌러 주세요 |
| stepManual | 거의 다 됐어요 | 목록에서 골라 주세요 |
| stepSku | 마지막이에요 | 수량만 맞으면 끝입니다 |

구현: `STEP_PROGRESS`에 `hintGuide` 필드를 추가하고 `show()`에서 `guideOn() ? hintGuide : hint` 선택. 로직 분기 한 줄이면 된다.

4. `.guide-steps`의 현재 칸은 `STEP_PROGRESS[step].value`(33/66/100)로 판정: 33→①, 66→②, 100→③. `stepDone`은 `.prog` 자체가 `hidden`이므로 해당 없음.

### 4-3. 각 단계의 "지금 할 일" 배지
sell.html에서는 **배지를 쓰지 않는다.** 이유: 등록 화면은 애초에 한 화면에 할 일이 하나뿐이라(사진 드롭 하나, 후보 그리드 하나) 어디를 눌러야 할지 헷갈릴 여지가 없다. 배지를 붙이면 정보만 늘고 시선 경합이 생긴다.

예외 한 곳: **`stepResult`의 후보 그리드**. AI 1순위 후보 카드에 이미 표시가 있는지 dev가 확인하고, 없다면 ON에서만 1순위에 `.now-badge`를 붙이는 것을 검토. 단 **"AI가 고른 것"이지 "정답"이 아님이 읽히는 문구**여야 한다 → 배지 텍스트는 `지금 할 일`이 아니라 **`AI 추천`**. (AI 원칙: 판단은 사람이 한다.)

### 4-4. 등록 완료 시
`stepDone` 도달 시 `bumpSellCount()` 호출. 3회째면 다음 홈 진입에서 자동 졸업(1-3).

## 5. 어르신 배려 vs 젊은 판매자 — 밀도토글과의 관계

두 토글은 **직교한다.** 서로를 건드리지 않는다.

| | 안내 ON | 안내 OFF |
|---|---|---|
| **크게(기본)** | 처음 쓰는 어르신 — 기본 상태 | 익숙해진 어르신 (자동 졸업 후) |
| **보통(compact)** | 처음 쓰는 젊은 판매자 | 숙련 판매자 — 가장 담백 |

지켜야 할 것:
- 안내 모드가 밀도를 **자동으로 바꾸지 않는다.** "안내 켜면 글자도 커진다"는 예측 불가능한 동작이고, 화면이 두 곳 동시에 변하면 사용자가 무엇을 눌렀는지 잃는다.
- 반대로 밀도를 '보통'으로 바꿔도 안내는 그대로. 다만 compact에서 `.guide-steps`가 좁아지므로, 라벨을 **`품목`/`수량`으로 줄이는 반응형**을 둔다: `body[data-density='compact'] .gs`에서 축약 라벨 사용(`data-short` 속성 활용 또는 `.gs .full { display:none }`).
- 안내 요소도 전부 `--u` 비례이므로 compact에서 자동으로 작아진다. 별도 대응 불필요.
- **금지 목록**(과잉 방지): 화면 진입 툴팁 팝오버, 순차 스포트라이트 오버레이(딤 처리), 깜빡이는 화살표, 자동 스크롤, 모달 온보딩 5장. 전부 어르신에게 "화면이 잠겼다"로 읽힌다.

## 6. 접근성

### 6-1. 토글 버튼
```html
<button class="s-chip guide-toggle" id="guideBtn" type="button"
        role="switch" aria-checked="true" aria-label="따라 하기 안내">
  <span class="sw" aria-hidden="true"></span><span class="tx">안내 켜짐</span>
</button>
```
- `role="switch"` + `aria-checked` — 켬/끔이 있는 것이므로 `aria-pressed`보다 `switch`가 정확하다. (밀도토글은 `aria-pressed`를 쓰지만 그건 "다음 행동" 버튼이라 다르다. 이 차이를 주석으로 남길 것.)
- `aria-label`은 **상태를 뺀 이름**(`따라 하기 안내`)으로 고정. 이름 안에 "켜짐"을 넣으면 스크린리더가 "따라 하기 안내 켜짐, 켜짐"으로 두 번 읽는다. 상태는 `aria-checked`가 담당.
- 눈에 보이는 텍스트(`안내 켜짐`)와 접근 이름(`따라 하기 안내`)이 다르므로, **보이는 텍스트가 접근 이름에 포함**되도록 `aria-label="따라 하기 안내 켜짐"`으로 갈지 dev가 택일 — 음성 명령 사용자 배려(WCAG 2.5.3 Label in Name) 기준으로는 후자가 안전. **권장: `aria-label` 없이 버튼 텍스트를 그대로 이름으로 쓰고 `role="switch"` + `aria-checked`만 부여.** 가장 단순하고 규격에 맞다.

### 6-2. 상태 변경 알림
토글 클릭 시 화면이 바뀌므로 라이브 리전으로 한 줄 알린다.
```html
<p class="visually-hidden" id="guideLive" aria-live="polite"></p>
```
- ON → `따라 하기 안내를 켰습니다. 지금 할 일은 사진 찍기입니다.`
- OFF → `따라 하기 안내를 껐습니다.`
- `.visually-hidden`은 sell.html에서 이미 쓰이는 클래스 — 재사용.

### 6-3. 강조의 비색상 전달
테두리 색만으로 "현재 단계"를 알리지 않는다. 이미 (C) 배지 텍스트("지금 할 일")와 `.guide-steps`의 숫자·`aria-hidden` 밖 대체 경로로 전달되므로 충족. 색맹 사용자 대비 `.shoot` 강조는 **테두리 두께 3px**로 두께 차이도 함께 준다.

### 6-4. 대비
- `.now-badge`: `--brand`(#00c46a) 배경 + 흰 글자 = 대비 약 2.1:1로 **AA 미달**. 배지 배경은 `--brand-strong`(#009a53, 흰 글자 대비 약 3.5:1) 또는 배지를 **`--brand-tint` 배경 + `--brand-strong` 글자**로 반전할 것. **권장: tint 배경 + strong 글자** (흰 카드 위에서 톤이 부드럽고 대비도 확보).
- 다크모드(`base.css` 95줄~)에서 `--brand`가 #00d477로 바뀌므로 하드코딩 없이 토큰만 쓰면 자동 대응. dev는 다크모드에서 `.guide-steps` 비활성 칸이 안 보이지 않는지 확인.

### 6-5. 포커스
- 안내 ON으로 켠 직후 포커스를 `.shoot`으로 **옮기지 않는다.** 사용자가 누른 건 토글이고, 포커스가 튀면 방향을 잃는다. 6-2의 라이브 리전으로 충분.
- `.shoot` 강조 링(`box-shadow`)이 기존 `:focus-visible` 링과 겹치지 않는지 확인. 겹치면 포커스 링을 `outline`(별도 레이어)으로 분리.

| 강조색 | 금색 테두리 | 브랜드 그린 + tint 링 | 우리 화면의 행동색이 이미 그린. 색 추가는 강조를 희석 |
